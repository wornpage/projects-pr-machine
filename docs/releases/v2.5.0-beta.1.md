# Wornpage PR Machine 2.5.0-beta.1

The first public beta of Wornpage PR Machine turns reviewed agent work into verified draft pull requests while keeping merge authority with the repository owner.

## What ships

- `projects-pr doctor`, `prepare`, `status`, `finalize`, and `abort`
- one-worker, isolated-worktree execution
- verification fixed and SHA-256-bound before work starts
- exact repository, local/remote base commit, branch, refspec, and PR identity checks
- resumable schema-v2 receipts with bounded recovery commands
- optional bottom-to-top draft stacks through the official `github/gh-stack` extension
- the `projects-pack-delegation` Codex integration source and public protocol contracts

## Public use evidence

The public Wornpage Projects WebMCP Challenge repository records 32 merged PRs created on `projects-pr/task-*` branches from Projects pack handoffs between August 27 and September 1, 2026. Their PR bodies require owner review and state that the controller does not merge or enable auto-merge.

This is evidence of repeated use, not a claim of autonomous authorship, independent GitHub review, universal green CI, time saved, or quality causation.

## Safety boundary

The controller never delegates work, accepts its own evidence, merges, enables auto-merge, closes a PR, deploys, or completes a parent pack. The verification command is owner-supplied arbitrary shell input: it is fixed, stored verbatim, and hashed, but not sandboxed. Do not put secrets in it.

## Beta limitations

- Run one controller process per repository; cross-process lifecycle locking is not implemented.
- Child Git, shell, and GitHub processes have no controller-enforced timeout.
- Tests inject Git/GitHub effects and do not create a real remote PR.
- npm registry publication is deferred until trusted publishing is configured; install this release's tarball directly.
